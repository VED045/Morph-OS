# Phase 6 — notifications and controls

NotificationListenerService requires Android authorization. Active cards are bounded to 100; actions forward existing PendingIntents and omit reply inputs. Local grouping separates conversations/media/packages. Optional history is off by default, bounded to 100, encrypted with an Android Keystore AES-GCM key and written atomically. Delete/revoke paths clear displayed data. Contents are never sent to the model. Control center reads real battery/storage/memory/device values, opens Internet/Bluetooth/settings panels, adjusts media volume and launcher-window brightness, and uses authorized MediaSession controllers. The optional activity-owned floating panel can be moved and closed; Android may remove it when the owner is destroyed.

Verified before Phase 7: 18 Android unit tests, 6 API 36 instrumentation tests, debug build and lint. Notification-denied dashboard check passes. Lint had an internal FIR engine failure; a fresh single-worker lint run passed without disabling analysis. Authorized notifications/history/revocation/overlay and real media transport require manual integration checks. Cloud summaries, AI grouping, reply actions and OS notification bubbles remain backlog. SystemUI is not replaced.
